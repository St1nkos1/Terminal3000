# Terminal3000 — дизайн

- **Дата:** 2026-09-28
- **Статус:** согласован и реализован по плану `docs/superpowers/plans/2026-09-28-terminal3000.md`
- **Репозиторий:** `github.com/St1nkos1/Terminal3000` (публичный, MIT)

## 1. Зачем

Автор работает в терминале с несколькими сессиями Claude Code одновременно. Стандартное окно PowerShell для этого неудобно по всем четырём пунктам:

1. **Поиск сессии.** Много окон, непонятно, где какой проект и кто из Claude ждёт ответа или закончил.
2. **Ввод-вывод.** Копирование, вставка, прокрутка, многострочный ввод, выделение, горячие клавиши.
3. **Нет обзора.** Нельзя держать несколько сессий и консоль проекта на одном экране.
4. **Ручной запуск.** Каждый раз `cd` в проект, `claude`, `--resume` для продолжения.

Terminal3000 — своё десктоп-приложение-терминал для Windows. Обычные консоли и сессии Claude собраны в нём в одном окне: боковая панель со статусами, сплиты, палитра быстрого запуска, уведомления и восстановление всего после перезапуска.

Проект публикуется на GitHub, чтобы им могли пользоваться друзья автора. Поэтому в репозитории нет захардкоженных личных путей, секретов и чужого контента, а установка описана в README.

## 2. Критерии успеха

- Открыты 3+ сессии Claude в разных проектах и консоли, и за секунду видно, какая сессия ждёт ответа, какая работает, а какая закончила.
- Статус в панели меняется не позже чем через 1 секунду после события хука.
- Уведомление приходит, только если автор не смотрит на эту вкладку. Клик по уведомлению открывает нужную вкладку.
- После закрытия и повторного открытия приложения на месте те же вкладки и сплиты, а Claude продолжает те же разговоры.
- Профиль PowerShell автора с ключами загружается во всех вкладках, в том числе в тех, где запущен Claude. Приложение профиль не читает.
- Друг на чистой Windows 10/11 с Node.js ставит и запускает проект по README: `git clone` → `npm install` → `npm start`. Visual Studio Build Tools не нужны.

## 3. Не делаем (YAGNI)

- Фоновый демон в стиле tmux: сессии живут, пока открыто окно. Жизнь после перезапуска обеспечивает `--resume`.
- Сохранение содержимого терминалов на диск: там могут быть секреты.
- SSH, удалённые хосты, WSL-специфику. WSL можно запустить как обычную оболочку, но отдельно не поддерживается.
- Редактор тем, плагины, автообновление.
- Официальную поддержку macOS и Linux. Код специально не привязан к Windows там, где это ничего не стоит, но другие ОС не тестируются.

## 4. Интерфейс

### 4.1. Раскладка

```
┌─ Terminal3000 ─────────────────────────────────────────────────────────┐
│ ▾ MyWebShop               │ MyWebShop · claude          ● ждёт разрешения│
│   ● claude     ждёт  2м   │                                            │
│   ▪ pwsh                  │  ╭────────────────────────────────────╮    │
│ ▾ DataPipelineTester      │  │ Allow Bash: npm test ?  1.Yes 2.No │    │
│   ◐ claude  работает 14с  │  ╰────────────────────────────────────╯    │
│ ▾ Terminal3000            │                                            │
│   ✔ claude    готово      ├────────────────────────────────────────────┤
│   ✕ claude    упала       │ PS C:\...\MyWebShop> _                     │
│                           │                                            │
│ [+] Ctrl+Shift+T          │                                            │
└───────────────────────────┴────────────────────────────────────────────┘
```

- **Боковая панель.** Сессии сгруппированы по папке проекта. У каждой сессии иконка статуса, название и время в текущем статусе. Порядок сам не меняется. Панель можно свернуть.
  - Правый клик по заголовку группы открывает у курсора меню нового сеанса в папке группы: «Claude: новый разговор», «Claude: продолжить последний», «Claude: выбрать разговор…» (открывает палитру со списком разговоров), затем через линию консоли, оболочка по умолчанию первой. Пока разговоры читаются или если их нет, «продолжить» и «выбрать» видны, но серые: меню не прыгает под курсором. Меню закрывается выбором, `Esc`, кликом мимо, потерей фокуса или изменением размера окна; стрелки перескакивают серые пункты, `Enter` выбирает. У края окна меню сдвигается внутрь.
- **Основная область.** Дерево сплитов из горизонтальных и вертикальных делений, пропорции перетаскиваются мышью. Любую вкладку можно поставить в любую панель.
  - **Консоль под Claude** (`consoleUnderClaude`, по умолчанию включено). Claude-вкладка, которая приходит на экран (переключение из панели, палитры, `Ctrl+1…9`, `Ctrl+Shift+J`, `Ctrl+Tab`, по уведомлению, или новая вкладка без явного сплита), встаёт вместе с консолью своего проекта снизу — той же, что показывает ``Ctrl+` ``. Место — активная панель, а если она входит в пару «Claude над консолью», то вся пара: пара другого проекта сменяется целиком, пропорции остаются. Консоли у проекта нет — она создаётся и встаёт под Claude, как только готова; фокус остаётся на Claude. Консоль, уже стоящая на экране в другом месте, не дублируется. Claude уже на экране — клик только переводит фокус, поэтому убранная ``Ctrl+` `` консоль не возвращается, пока Claude не уйдёт с экрана. Пока зажат `Ctrl` при `Ctrl+Tab`, консоли не создаются: недостающая создаётся для вкладки, на которой отпустили `Ctrl`. На одну папку одновременно создаётся одна консоль. Консоль, явный сплит и `false` в настройке — по-старому: вкладка встаёт на место активной.

### 4.2. Статусы

| Иконка | Статус | Смысл |
|---|---|---|
| `◌` серый | `sleeping` / спит | Вкладка восстановлена, но процесс ещё не запущен (ленивое восстановление) |
| `…` серый | `starting` / запуск | Процесс запущен, `SessionStart` ещё не пришёл. Если хуки не установлены или 30 с нет событий, показывается как «без статусов» |
| `○` серый | `idle` / свободна | Claude ждёт новую задачу, результат вы уже видели |
| `◐` синий | `working` / работает | Claude думает или выполняет инструменты |
| `●` жёлтый | `waiting` / ждёт вас | Нужны разрешение, ответ на вопрос или ввод |
| `✔` зелёный | `done` / готово | Claude закончил, а вы ещё не смотрели. При открытии вкладки статус становится `idle` |
| `✕` красный | `crashed` / упала | `claude` завершился с ненулевым кодом, или вкладку не удалось запустить |
| `▪` серый | `shell` / консоль | Обычная консоль без Claude (или Claude в ней завершился штатно) |

### 4.3. Клавиши

Команды приложения висят на `Ctrl+Shift+…`: терминальные программы не отличают их от `Ctrl+…`, поэтому конфликтов с клавишами Claude Code (`Ctrl+T`, `Ctrl+R`, `Ctrl+O`, `Ctrl+B`, `Ctrl+G`…) нет. Все сочетания переназначаются в `config.json`.

| Клавиша | Действие |
|---|---|
| `Ctrl+Shift+P` | Палитра: нечёткий поиск по открытым вкладкам, проектам, прошлым разговорам Claude и командам |
| `Ctrl+Shift+T` | Новая вкладка: первым пунктом консоль в домашней папке, затем выбор папки или проекта, а в проекте — `claude` (новый / продолжить последний / выбрать разговор) или консоль |
| `Ctrl+1…9` | Перейти к N-й вкладке в порядке панели |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | Следующая / предыдущая по недавности использования (MRU) |
| `Ctrl+Shift+J` | Перейти к следующей вкладке в статусе `waiting` или `done` (сначала `waiting`) |
| ``Ctrl+` `` | Показать или скрыть консоль проекта под текущей вкладкой |
| `Ctrl+Shift+\` / `Ctrl+Shift+-` | Разделить вертикально / горизонтально, во вторую панель выбрать вкладку |
| `Ctrl+Shift+F` | Поиск по выводу текущей вкладки |
| `F2` | Переименовать вкладку |
| `Ctrl+Shift+W` | Закрыть вкладку (с подтверждением, только если Claude в ней работает или ждёт ответа). То же делают крестик на строке вкладки и в заголовке панели и средняя кнопка мыши по строке |
| `Ctrl+Shift+M` | «Не беспокоить»: уведомления и звук выключены, статусы продолжают работать |

Сочетания сравниваются по физической клавише (`event.code`), поэтому работают в любой раскладке. Сочетание без `Ctrl` или `Alt` допускается только для `F1…F24`, иначе оно перехватило бы обычный ввод. «Не беспокоить» действует до перезапуска приложения, начальное значение — `notifications.doNotDisturb`.

### 4.4. Ввод и вывод

- **`Ctrl+C`** при выделенном тексте копирует, без выделения отправляет прерывание в процесс.
- **Вставка.** `Ctrl+V` и правая кнопка мыши вставляют текст в режиме bracketed paste. Если в буфере обмена картинка, а текста нет, в процесс уходит сырой `Ctrl+V` (`\x16`), чтобы Claude сам вставил скриншот.
- **`Shift+Enter`** отправляет `\x1b\r`: это перенос строки в поле ввода Claude, как после `/terminal-setup` в VS Code.
- **Перетаскивание файла** в окно вставляет путь в кавычках.
- **Прочее.** Кликабельные ссылки, история прокрутки на 10 000 строк (настраивается), рендер через WebGL с откатом на DOM-рендерер (аддон canvas несовместим с xterm 6; WebGL выключается опцией `webgl`), Unicode 11 (кириллица и эмодзи).
- **Внешний вид.** Тёмная тема, шрифт по умолчанию `Cascadia Mono, Consolas, monospace` размером 14.

## 5. Архитектура

### 5.1. Стек

TypeScript, Electron 44, `electron-vite`, `@xterm/xterm` 6 с аддонами (`fit`, `webgl`, `search`, `web-links`, `unicode11`), `node-pty` 1.1 (готовые N-API бинарники для `win32-x64` и `win32-arm64`, свои `conpty.dll` и `OpenConsole.exe`), React для панели и палитры (без `@vitejs/plugin-react`: JSX собирает esbuild), Vitest, Playwright (Electron), `electron-builder` (NSIS-установщик).

### 5.2. Процессы и поток данных

```
 ┌──────────── Renderer (окно, без доступа к Node) ───────────┐
 │ Sidebar · PaneTree · TerminalView(xterm) · Palette · Keys  │
 └───────────────▲──────────────────────────┬─────────────────┘
       состояние, │ данные pty    ввод, resize, │ команды
                  │  (IPC через preload/contextBridge)
 ┌───────────────┴──────────────────────────▼─────────────────┐
 │ Main: SessionStore ◄─ StatusMachine ◄─ HookServer          │
 │        │   ▲                              ▲ POST 127.0.0.1  │
 │        ▼   │                              │ + token         │
 │  PtyManager ── node-pty ── powershell ── claude ── хук ─────┘
 │  Notifier · Persistence · Config · ProjectIndex · HookInstaller
 └─────────────────────────────────────────────────────────────┘
```

Процессы pty живут в main. Renderer только отображает, поэтому его перезагрузка сессии не убивает (см. §11).

### 5.3. Модули main-процесса

У каждого модуля одна задача и узкий интерфейс. Модули с логикой тестируются без Electron.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `config.ts` | Читает и проверяет `config.json`, подставляет значения по умолчанию, отслеживает изменения файла | fs |
| `launch.ts` | Чистая функция: `(вкладка, config) → { file, args, cwd, env }` для pty | — |
| `pty-manager.ts` | Запуск, ввод, resize, kill процессов `node-pty`. Кольцевой буфер вывода (200 КБ на вкладку, только в памяти). Отслеживает время последнего вывода | node-pty, launch |
| `status-machine.ts` | Чистая функция `(состояние вкладки, событие) → новое состояние` | — |
| `session-store.ts` | Список вкладок и их состояние. Применяет события через `StatusMachine`, рассылает изменения | status-machine |
| `hook-server.ts` | HTTP на `127.0.0.1:<случайный порт>`, проверка токена, разбор событий хука | http |
| `hook-installer.ts` | Установка, обновление и удаление хуков в `~/.claude/settings.json` | fs |
| `notifier.ts` | Уведомления Windows, мигание окна, бейдж на иконке в панели задач. Звуком управляет renderer по команде | Electron |
| `project-index.ts` | Список проектов и прошлых разговоров Claude | fs |
| `persistence.ts` | Атомарное чтение и запись `workspace.json` | fs |
| `controller.ts` | Жизненный цикл вкладок: запуск, перезапуск, восстановление, ввод, вид для `workspace.json` и правило видимости | session-store, pty-manager, launch |
| `osc.ts`, `ring-buffer.ts` | Поиск OSC 7777 в потоке pty (в том числе разрезанного между чанками), кольцевой буфер вывода | — |
| `banners.ts` | Баннеры про хуки, сервер статусов и повреждённые файлы | — |
| `paths.ts`, `ipc-guards.ts`, `log.ts`, `sound-file.ts` | Пути данных, проверка аргументов IPC, лог с ротацией, чтение файлов звука по конфигу | fs |
| `index.ts` | Сборка всего вместе, окно, IPC, единственный экземпляр, аргументы командной строки | всё выше |

`shared/` хранит типы и контракт IPC, общие для main, preload и renderer. `hooks/t3000-hook.js` — отдельный скрипт на чистом Node без зависимостей.

### 5.4. Renderer

- **`Sidebar`, `Palette`** — React-компоненты, получают состояние из main.
- **`PaneTree`** — React-дерево сплитов. Узлы: `split` (направление, пропорции, дети) или `pane` (id вкладки).
- **`TerminalView`** — класс, который напрямую управляет экземпляром xterm и живёт вне цикла рендеринга React. На каждую вкладку свой экземпляр. Скрытые вкладки не уничтожаются, а открепляются от DOM, так что прокрутка сохраняется.
- **`keybindings.ts`** — разбирает сочетания клавиш из конфига и перехватывает их до того, как они попадут в xterm.
- **`sounds.ts`** — встроенные звуки (файл `faceit` из `assets/sounds/` и синтезированные через WebAudio `alert`, `chime`, `low`) и пользовательские файлы. Одновременно звучит один звук, и он обрывается, когда открывают вкладку, к которой он относится.

## 6. Данные

Все файлы лежат в `%APPDATA%\Terminal3000\`. В репозиторий ничего из этого не попадает.

### 6.1. `config.json`

Создаётся со значениями по умолчанию при первом запуске. Команда палитры «Открыть настройки» открывает его в редакторе по умолчанию. Изменения подхватываются без перезапуска.

```jsonc
{
  "defaultShell": "powershell",
  "shells": {
    "powershell": { "file": "powershell.exe", "args": ["-NoLogo"] },
    "cmd":        { "file": "cmd.exe", "args": [] },
    "gitbash":    { "file": "C:/Program Files/Git/bin/bash.exe", "args": ["--login", "-i"] }
  },
  "claudeCommand": "claude",
  "projectRoots": [],                 // папки, подпапки которых тоже считаются проектами
  "restore": "lazy",                  // "lazy" | "eager"
  "font": { "family": "Cascadia Mono, Consolas, monospace", "size": 14 },
  "scrollback": 10000,
  "webgl": true,                      // false — DOM-рендерер вместо WebGL
  "consoleUnderClaude": true,         // Claude-вкладка встаёт на экран с консолью своего проекта снизу
  "status": { "silenceMs": 4000 },
  "notifications": {
    "toast": true, "flashFrame": true, "badge": true,
    "messagePreview": true,           // показывать в уведомлении текст от Claude
    "doNotDisturb": false
  },
  "sounds": {
    "volume": 0.8,
    "waiting": "builtin:faceit",      // builtin:faceit | builtin:alert | builtin:chime | builtin:low
    "done":    "builtin:faceit",      // или путь к своему файлу; относительный — от %APPDATA%\Terminal3000\
    "crashed": "builtin:low"          // "" или "none" — без звука; неизвестный builtin:… играет как alert
  },
  "keybindings": { "palette": "Ctrl+Shift+P", "newTab": "Ctrl+Shift+T" }  // полный список действий и значений по умолчанию — §4.3
}
```

Звук FACEIT accept (`assets/sounds/faceit-accept.mp3`, 7,9 с) лежит в репозитории и по решению автора включён у всех по умолчанию на «ждёт» и «готово». В сборке он копируется в `resources/sounds/`. Кто хочет другой звук, указывает свой файл или один из синтезированных. `.gitignore` по-прежнему исключает все остальные аудиофайлы, чтобы случайные чужие звуки не попадали в репозиторий.

### 6.2. `workspace.json`

Записывается атомарно (временный файл, затем rename) не чаще раза в 500 мс и обязательно при выходе, в том числе при выходе из Windows и перезагрузке (`session-end` окна).

```jsonc
{
  "version": 1,
  "tabs": [
    { "id": "t_7f3a", "title": "MyWebShop", "cwd": "C:/Projects/MyWebShop",
      "kind": "claude", "shell": "powershell", "claudeSessionId": "9bbedab8-…", "customTitle": false }
  ],
  "layout": { "type": "split", "dir": "row", "sizes": [0.6, 0.4],
              "children": [ { "type": "pane", "tab": "t_7f3a" }, { "type": "pane", "tab": "t_91c0" } ] },
  "activeTab": "t_7f3a",
  "sidebar": { "collapsed": false, "collapsedGroups": [] }
}
```

Хранятся только папка, тип, оболочка, `claudeSessionId`, названия и последний размер терминала (`termSize`: с ним стартуют вкладки, которые ещё не показаны). **Вывод терминалов и переменные окружения на диск не пишутся никогда.**

### 6.3. Индекс проектов

`ProjectIndex` строит список из двух источников:

1. **`~/.claude/projects/*/*.jsonl`.** Имена папок там искажены (кириллица превращается в `-----`), поэтому настоящий путь берётся из поля `cwd` первых записей файла. Из каждого файла читаются только первые 64 КБ: `cwd`, `sessionId` (имя файла), первый пользовательский запрос (обрезается до 80 символов и служит названием разговора) и время изменения файла. Результат кешируется по mtime.
2. **Подпапки из `config.projectRoots`.**

Проект — уникальный `cwd`. Проекты, чьих папок больше нет, в палитре не показываются.

## 7. Запуск вкладок

`launch.ts` формирует команду. Переменные окружения каждой вкладки: окружение приложения без служебных `ELECTRON_*`, без окружения npm-скрипта при запуске через `npm start` (`npm_*`, `INIT_CWD`, `NODE` и записи `node_modules.bin` в начале `PATH`) и без переменных терминала, из которого запустили приложение (`WT_SESSION`, `WT_PROFILE_ID`, `TERM_PROGRAM_VERSION`, `VSCODE_*`, `GIT_ASKPASS` от VS Code), плюс `T3000_TAB_ID`, `T3000_PORT`, `T3000_TOKEN`, `TERM_PROGRAM=Terminal3000`, `COLORTERM=truecolor`.

- **Консоль PowerShell:** `powershell.exe -NoLogo`, без `-NoProfile`. **Профиль пользователя загружается штатно, приложение его не читает.**
- **Вкладка Claude** запускается **через PowerShell**, чтобы Claude получил окружение из профиля, в том числе ключи:

  ```
  powershell.exe -NoLogo -NoExit -Command "& { $global:LASTEXITCODE = $null; claude --resume '<id>'; $ok = $?;
    $c = $LASTEXITCODE; if ($null -eq $c) { $c = [int](-not $ok) };
    [Console]::Write([char]27 + ']7777;t3000;claude-exit;' + $c + [char]7) }"
  ```

  Для нового разговора вместо `--resume '<id>'` ничего не передаётся, для «продолжить последний» передаётся `--continue`. Благодаря `-NoExit` после выхода из Claude вкладка остаётся консолью в папке проекта. Служебная последовательность OSC 7777 сообщает код выхода `claude`. Её находит main в потоке pty (`osc.ts`), поэтому `claude-exit` приходит и от скрытых вкладок; renderer только глушит её через `parser.registerOscHandler`, на экран она не попадает. `$LASTEXITCODE` сбрасывается перед запуском: профиль мог оставить там 0 от другой программы. Если `claude` не нашёлся, код берётся из `$?`. Id разговора с символами вне `[A-Za-z0-9_.-]` не подставляется: вкладка начинает новый разговор.
- **cmd и Git Bash** запускаются как обычные консоли. Вкладку Claude с ними не создаём: для Claude всегда используется PowerShell.
- **`claude`, запущенный вручную в любой консоли**, тоже отслеживается: хук получает `T3000_TAB_ID` из окружения вкладки. По первому `SessionStart` вкладка становится Claude-вкладкой, а при восстановлении запускается через обёртку выше. `SessionStart` главной сессии также меняет папку вкладки на `cwd` из хука: `claude --resume` ищет разговор по папке запуска.

## 8. Статусы и хуки

### 8.1. Хук `hooks/t3000-hook.js`

Скрипт на Node без зависимостей. Порядок работы:

1. Если нет `T3000_TAB_ID`, `T3000_PORT` или `T3000_TOKEN`, **сразу `exit 0`**: это `claude`, запущенный вне Terminal3000.
2. Читает stdin, не дольше 1 секунды.
3. Разбирает JSON и оставляет только нужные поля: `hook_event_name`, `session_id`, `cwd`, `source`, `reason`, `notification_type`, `message`, `last_assistant_message` (обрезается до 200 символов), флаг наличия `agent_id`. Добавляет `ts = Date.now()`.
4. Отправляет `POST http://127.0.0.1:$T3000_PORT/event` с заголовком `x-t3000-token`. Таймаут запроса 1 секунда.
5. Любая ошибка проглатывается. Код выхода всегда `0`, в stdout ничего не пишется.

### 8.2. Регистрация в `~/.claude/settings.json`

Используется exec-форма: оболочка не участвует, и пути не нужно экранировать. Также ставится `async: true`, чтобы хук никогда не блокировал Claude.

```json
{ "type": "command", "command": "node",
  "args": ["C:/…/Terminal3000/hooks/t3000-hook.js"],
  "async": true, "timeout": 5 }
```

Хук регистрируется на события `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `Notification`, `Stop`, `SessionEnd`.

Правила `HookInstaller`:

- При первом запуске спрашивает согласия. Кнопка «Установить хуки» также доступна в баннере и палитре.
- Перед любым изменением сохраняет `settings.json.bak-<YYYYMMDD-HHmmss>` рядом с оригиналом.
- Свои записи узнаёт по `t3000-hook` в `args` (или в `command` для запасного варианта). Чужие хуки и прочие ключи не трогает, порядок ключей сохраняет.
- Повторная установка идемпотентна. Если путь к скрипту изменился, например приложение переехало, записи обновляются, а не дублируются. При каждом запуске приложение сверяет путь и при расхождении предлагает обновить.
- «Удалить хуки» убирает только свои записи.
- Если `settings.json` не парсится, файл не трогается, а пользователю показываются путь и ошибка.
- **Запасной вариант без Node.** Если `node` не найден в `PATH` (установленная сборка у друга без Node), регистрируется `"command": "<путь>/Terminal3000.exe", "args": ["--t3000-hook"]`. В самом начале `index.ts`, до блокировки единственного экземпляра и до создания окна, приложение распознаёт этот флаг, выполняет ту же логику, что `t3000-hook.js`, и выходит. Задержка запуска Electron неважна, потому что хук асинхронный.

### 8.3. `HookServer`

- Слушает `127.0.0.1` на случайном свободном порту.
- Токен — 32 случайных байта на каждый запуск приложения, сравнивается за постоянное время.
- Тело запроса ограничено 16 КБ, поля проверяются по схеме.
- Событие с неизвестным `T3000_TAB_ID` игнорируется.

### 8.4. `StatusMachine`

Каждое событие хука обновляет `claudeSessionId` вкладки значением `session_id`. Поэтому `--resume` откроет правильный разговор при любом поведении `/clear`. Исключение — живая Claude-вкладка (свободна, работает, ждёт, готово): она привязана к своему разговору, и события другой сессии игнорируются целиком, кроме `SessionStart` с `source: clear` или `resume`. Такие события шлёт вложенный `claude -p` из Bash-инструмента или из хука пользователя: он получает тот же `T3000_TAB_ID`. События с `ts` старше последнего применённого отбрасываются: асинхронные хуки могут прийти не по порядку.

| Событие | Переход |
|---|---|
| процесс вкладки Claude запущен | → `starting` |
| `SessionStart` | → `idle`; для консольной вкладки ещё и `kind: claude`; при `source: compact` статус не меняется (сжатие идёт посреди работы); папка вкладки становится `cwd` из хука |
| `UserPromptSubmit`, `PostToolUse` | → `working` |
| `Notification`: `permission_prompt`, `elicitation_dialog`, `elicitation_url_dialog`, `agent_needs_input` | → `waiting`, в том числе когда разрешение просит сабагент |
| `Notification`: `elicitation_response`, `elicitation_complete` | → `working` |
| `Notification`: `idle_prompt` | если `working` → `idle` (без уведомления); `waiting` не снимается, чтобы не потерять запрос разрешения |
| `Notification`: прочие (`auth_success`, `quota_*`, `agent_completed`) | без изменений |
| `Stop` | → `done`, если вкладка не видна в активном окне; иначе → `idle` |
| `SubagentStop` и события с `agent_id` | не меняют статус главной сессии (кроме `PostToolUse` → `working` и запросов разрешения → `waiting`); `kind` и `claudeSessionId` не трогают |
| `SessionEnd` с `reason ≠ clear` | → `shell` и `kind: shell`, даже если `claude-exit` не придёт (Claude запущен вручную); после `/clear` сразу придёт `SessionStart` |
| `claude-exit` с кодом 0 | → `shell` и `kind: shell`: вкладка восстанавливается консолью, как её оставили |
| `claude-exit` с кодом ≠ 0 | → `crashed` |
| процесс вкладки (оболочка) завершился | вкладка остаётся открытой с текстом «Процесс завершён (код N). Enter — перезапустить»; консоль → `shell`, Claude-вкладка → `crashed` |
| вкладка стала видимой в активном окне | `done` → `idle` |

При запуске процесса, `claude-exit`, выходе процесса и переходе в консоль запоминается `lastTs = now`, поэтому поздние хуки старого процесса не меняют новую вкладку. Автоответы терминала (focus reporting, ответы DA и CPR) вводом пользователя не считаются.

**Запасные правила** на случай, когда Claude Code не присылает хук. Прерывание через `Esc` не вызывает `Stop`, отказ в разрешении тоже не порождает события.

- Любой ввод во вкладку со статусом `waiting` → `working`.
- В `working` нет вывода `status.silenceMs` (4 с) → `idle` без уведомления. Работает, потому что пока Claude работает, его спиннер постоянно обновляется.
- `idle_prompt` через 60 секунд служит второй страховкой.

Все переходы, включая запасные, покрываются табличными тестами.

## 9. Уведомления и звук

- **Когда.** При переходе в `waiting`, `done` или `crashed`, и только если вкладка не видна в активном окне. Повтор того же статуса в той же вкладке не уведомляет. «Не беспокоить» отключает уведомление Windows, звук и мигание, а статусы и бейдж продолжают работать.
- **Уведомление Windows.** Заголовок «`<проект>` · ждёт разрешения / готово / упала». Текст: `message` из `Notification` или начало `last_assistant_message` из `Stop`, если `notifications.messagePreview` включён. Текст сворачивается в одну строку и обрезается до 200 символов. Клик открывает окно и переключает на вкладку. Приложение задаёт `AppUserModelId` `com.st1nkos1.terminal3000`. В режиме разработки Windows может подписывать уведомления как «Electron»; это нормально и описано в README.
- **Звук.** По умолчанию на «ждёт» и «готово» играет `builtin:faceit` (FACEIT accept), на «упала» — синтезированный `low`. Синтезированные `alert` и `chime` доступны как альтернатива без файлов. Для любого события можно указать путь к своему файлу. Играет один звук за раз: новый прерывает предыдущий. Звук обрывается, когда открывают вкладку, к которой он относится. Если файл не найден, играет встроенный сигнал, а в лог пишется предупреждение. Файл читает main по виду события (`loadSound(kind)`): renderer не может попросить произвольный путь. Пустая строка или `none` — без звука.
- **Панель задач.** `flashFrame`, пока окно не активно. На иконке бейдж: красный кружок с числом вкладок в `waiting` и `done`, картинка рисуется на canvas. Бейдж пропадает, когда ждущих вкладок нет.

## 10. Восстановление и запуск приложения

- **Запуск.** Читается `workspace.json`, и каждая вкладка создаётся заново:
  - при `restore: "lazy"` (по умолчанию) вкладка получает статус `sleeping`, а процесс стартует при первом открытии;
  - активная вкладка стартует сразу;
  - при `"eager"` стартуют все вкладки.
- **Вкладки Claude.** С `claudeSessionId` запускаются как `claude --resume <id>`, без него как `claude`. Разговор перерисовывает сам Claude.
- **Единственный экземпляр.** Повторный запуск разворачивает уже открытое окно. `Terminal3000.exe <папка>` открывает в нём новую консоль в этой папке.
- **Первый запуск.** Показывается приветствие с предложением установить хуки и коротким списком клавиш.

## 11. Ошибки

| Ситуация | Поведение |
|---|---|
| Упал или перезагрузился renderer | Main перезагружает окно, не больше 3 раз в минуту. Процессы pty живы, вкладки подключаются заново и перерисовываются из кольцевого буфера в памяти |
| Хук упал, завис или Claude его не вызвал | Хук асинхронный, всегда `exit 0`, с таймаутом. Статус подстраховывают запасные правила §8.4 |
| Хуки не установлены или путь устарел | Баннер «Статусы недоступны — установить или обновить хуки?» |
| `settings.json` не парсится | Не трогаем, показываем путь и текст ошибки |
| Папки вкладки больше нет | Вкладка `crashed` с текстом «Папка не найдена», предлагается закрыть её или выбрать папку |
| `--resume` не нашёл разговор | `claude` завершится с ненулевым кодом → `crashed` с подсказкой: Enter начинает новый разговор в той же папке |
| Оболочка не найдена | Вкладка `crashed` с текстом ошибки и выбором другой оболочки |
| `workspace.json` или `config.json` битые | Битый файл переименовывается в `*.broken-<дата>`, берутся значения по умолчанию, показывается уведомление. Файл, который просто не читается (занят, нет прав), не трогается |
| Сбой при запуске | Окно с текстом ошибки, процесс завершается: блокировка единственного экземпляра не остаётся висеть |
| Окно закрывают, пока Claude работает или ждёт | Вопрос со списком таких вкладок. При выходе из приложения и завершении сеанса Windows вопроса нет |
| Не удалось занять порт | Повтор с другим случайным портом, до 5 попыток, затем баннер |

**Логи** пишутся в `%APPDATA%\Terminal3000\logs\main.log` с ротацией, 1 МБ × 3 файла. В лог попадают только события приложения: запуск и завершение вкладок, переходы статусов, ошибки. **Вывод терминалов, переменные окружения и текст сообщений Claude в лог не попадают.**

## 12. Безопасность и приватность

- **Профиль PowerShell** загружается штатно и приложением не читается.
- **На диск не пишутся** вывод терминалов, переменные окружения и сообщения Claude. Текст Claude появляется только в уведомлении Windows, и это отключается флагом `messagePreview`.
- **`HookServer`** слушает только `127.0.0.1`, с токеном на каждый запуск и ограничением размера тела.
- **Окно** работает с `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Наружу через `contextBridge` открыт только узкий типизированный API. Ссылки открываются во внешнем браузере через `shell.openExternal` и только по `http(s)`.
- **Репозиторий** не содержит личных путей и секретов. Единственный аудиофайл — `assets/sounds/faceit-accept.mp3` (см. §14 про права).

## 13. Тестирование

Разработка идёт по TDD: сначала тест, потом код.

- **Unit (Vitest)** для чистой логики без Electron:
  - `status-machine`: таблица всех переходов, включая запасные правила, порядок по `ts`, события субагентов;
  - `hook-installer`: пустой файл, чужие хуки, повторная установка, смена пути, удаление, бэкап, битый JSON, запасной вариант без Node;
  - `project-index`: тестовые `.jsonl`, кириллические пути, отсутствующие папки, кеш;
  - `persistence`: сохранение и загрузка, атомарность, битый файл;
  - `launch`: команды для всех типов вкладок, окружение без `ELECTRON_*`, экранирование id в `--resume`;
  - `keybindings`: разбор сочетаний;
  - `config`: значения по умолчанию, проверка.
- **Интеграционные:** `hook-server` вместе с настоящим процессом `t3000-hook.js`, проверяются:
  - корректное событие доходит;
  - неверный токен отклоняется;
  - без `T3000_TAB_ID` хук выходит мгновенно и ничего не отправляет;
  - при недоступном сервере хук выходит с кодом 0 меньше чем за 1,5 с.
- **E2E (Playwright + Electron), один smoke-тест:** приложение стартует, открывается консоль, выполняется `echo t3000-ok`, вывод виден. После перезапуска вкладка восстановлена.
- **Ручная проверка на настоящем Claude.** Чек-лист в `docs/manual-checklist.md`: все переходы статусов, уведомление и клик по нему, звук и его обрыв, бейдж, восстановление с `--resume`, `/clear`, `Esc`, отказ в разрешении, работа ключей из профиля (проверяет автор).

## 15. Риски и шаг 0

Перед основной реализацией нужна короткая проверка на настоящем Claude Code 2.1.283. Для неё используется временный файл настроек через `claude --settings <файл>`, без изменения `~/.claude/settings.json`.

1. **Переменные окружения.** Видит ли хук переменные окружения родительского процесса (`T3000_TAB_ID`)? В документации это не описано. Если не видит, вкладку можно связывать с событием через `session_id` и `cwd`: pty знает своё `cwd`, а `SessionStart` сообщает `session_id`. Тогда дизайн §8 придётся скорректировать до реализации.
2. **Exec-форма и `async`.** Работают ли `"command": "node"` + `args` и `async: true` на Windows? Если нет, переходим на shell-форму с явным `"shell": "powershell"` или `"bash"`.
3. **`/clear`.** Меняет ли он `session_id`? На дизайн это не влияет (§8.4), но результат записывается в чек-лист.
4. **Совместимость.** Грузится ли `node-pty` 1.1 в Electron 44 без пересборки?
5. **Код выхода.** Доходит ли OSC 7777 из PowerShell 5.1 до xterm и не показывается ли на экране?

Если какой-то пункт не подтвердится, соответствующий раздел спецификации обновляется и заново согласуется с автором до продолжения работы.
