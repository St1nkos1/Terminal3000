# Ручная проверка Terminal3000

Проверяет автор на настоящем Claude Code, в своём профиле PowerShell. Результат — отметка и, если что-то не так, короткая заметка. Вывод терминалов и тексты Claude сюда не копировать.

Перед проверкой: `npm run build`, затем `npx electron .` (или установленная сборка из `npm run dist`).

## Шаг 0 спеки (§15)

Результаты проверки до начала реализации (процедура — в начале плана, раздел «Шаг 0»).

| Проверка | Результат |
|---|---|
| Хук видит `T3000_TAB_ID` из окружения родителя | да — 30.09.2026, Claude Code 2.1.285, `claude -p --settings <временный файл>` |
| Exec-форма `"command": "node"` + `args` и `async: true` работают | да — там же, события `SessionStart`, `UserPromptSubmit`, `Stop` пришли и с `async: true`, и без |
| `/clear` меняет `session_id` | проверяет автор в обычной сессии (в `-p` команды нет) |
| `node-pty` 1.1 грузится в Electron 44 без пересборки (`npm run check:pty`) | да — `node-pty OK (Electron 44.5.1)` |
| OSC 7777 из PowerShell 5.1 не виден на экране, `claude-exit` приходит | да — интеграционный тест `tests/integration/pty-manager.test.ts` на настоящем ConPTY; на экране проверяет автор |

## Профиль и запуск

- [ ] В новой консоли загрузился профиль PowerShell (ключи и функции из него доступны).
- [ ] Вкладка «Claude: новый разговор» запускает Claude, ему доступны ключи из профиля.
- [ ] `Terminal3000.exe <папка>` при закрытом приложении открывает консоль в этой папке; при открытом — разворачивает окно и добавляет вкладку.

## Статусы (§4.2, §8.4)

- [ ] `запуск` → `свободна` после старта Claude.
- [ ] Запрос → `работает`, время в статусе идёт.
- [ ] Запрос разрешения (`Allow Bash…`) → `ждёт`.
- [ ] Ответ на разрешение → `работает`.
- [ ] Отказ в разрешении (`No`) → через ~4 с тишины `свободна`.
- [ ] `Esc` посреди работы → через ~4 с `свободна`.
- [ ] Claude закончил во вкладке, которую не видно → `готово`; открыл вкладку → `свободна`.
- [ ] Claude закончил в видимой вкладке → сразу `свободна`, без уведомления.
- [ ] Запрос разрешения от сабагента (Task) → `ждёт`.
- [ ] `/compact` посреди работы статус не сбрасывает.
- [ ] `/clear` → `свободна`, после перезапуска приложения `--resume` открывает разговор после `/clear`.
- [ ] `/exit` → `консоль`, вкладка остаётся PowerShell в папке проекта, после перезапуска восстанавливается консолью.
- [ ] `claude --resume` с несуществующим id (поправить `claudeSessionId` в `workspace.json`) → `упала` с подсказкой; Enter начинает новый разговор, другая клавиша — консоль.
- [ ] `exit` в консоли → «Процесс завершён (код 0). Enter — перезапустить», Enter перезапускает.
- [ ] `claude`, набранный руками в обычной консоли, превращает вкладку в Claude-вкладку со статусами.
- [ ] После `cd` в другой проект и `claude` вкладка переезжает в группу этого проекта; после перезапуска приложения разговор открывается там же.

## Уведомления, звук, бейдж (§9)

- [ ] Уведомление приходит только для вкладки, которую не видно; заголовок «`<проект>` · ждёт разрешения / готово / упала».
- [ ] Текст уведомления — запрос разрешения или начало ответа Claude; с `"messagePreview": false` — «Claude ждёт вас» / «Claude закончил работу».
- [ ] Клик по уведомлению разворачивает окно и открывает вкладку.
- [ ] Играет FACEIT accept; новый звук обрывает предыдущий; звук обрывается, когда открыл вкладку.
- [ ] Кнопка окна мигает, пока окно не активно; перестаёт при активации.
- [ ] Бейдж на иконке показывает число вкладок в `ждёт` и `готово`, пропадает при нуле.
- [ ] `Ctrl+Shift+M`: нет уведомлений, звука и мигания, статусы и бейдж работают.
- [ ] Свой файл звука в `config.json` играет; путь к несуществующему файлу — `alert` и предупреждение в `logs\main.log`.

- [ ] Ссылка OSC 8 (например, из `gh pr list`) открывается в браузере без лишних вопросов.
- [ ] Баннер закрывается крестиком; новая ошибка в `config.json` показывает его снова.
- [ ] Закрытие окна, пока Claude работает, спрашивает подтверждение; «Отмена» оставляет окно.

## Восстановление (§10)

- [ ] После закрытия и повторного запуска те же вкладки, сплиты, имена, состояние панели.
- [ ] `restore: "lazy"`: неактивные вкладки `спит` и стартуют при открытии; `"eager"` — стартуют все.
- [ ] Вкладки Claude продолжают те же разговоры (`--resume`).
- [ ] Папку вкладки удалили → `упала`, «Папка не найдена», «Выбрать папку» чинит вкладку.

## Ввод и клавиши (§4.3, §4.4)

- [ ] Все сочетания §4.3 работают в английской и русской раскладке.
- [ ] `Ctrl+R`, `Ctrl+T`, `Ctrl+O`, `Ctrl+B`, `Ctrl+G` доходят до Claude, окно не перезагружается.
- [ ] `Ctrl+C` с выделением копирует, без выделения прерывает.
- [ ] Вставка текста в Claude — одним блоком (bracketed paste); скриншот в буфере без текста — Claude вставляет картинку.
- [ ] `Shift+Enter` — перенос строки в поле ввода Claude.
- [ ] Перетащенный файл вставляется путём в кавычках.
- [ ] Ссылка открывается в браузере.
- [ ] Кириллица и эмодзи отображаются без сдвигов.

## Хуки (§8.2)

- [ ] Claude, запущенный до установки хуков, через 30 с показывается как «без статусов».
- [ ] `settings.json`-симлинк (dotfiles) после установки хуков остаётся симлинком.
- [ ] Копия из исходников и установленная сборка не считают хуки друг друга устаревшими.

- [ ] Приветствие первого запуска ставит хуки; в `settings.json` только наши записи добавлены, рядом `settings.json.bak-…`.
- [ ] «Удалить хуки Claude Code» убирает только наши записи.
- [ ] Установленная сборка на машине без Node (или с `PATH` без Node): хуки ставятся как `Terminal3000.exe --t3000-hook`, статусы работают.

## Приватность (§12)

- [ ] В `%APPDATA%\Terminal3000\` нет вывода терминалов и текстов Claude: только `config.json`, `workspace.json`, `logs\`.
- [ ] В `logs\main.log` только события приложения.
